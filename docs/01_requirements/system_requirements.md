## 1. 背景・目的

### 1.1 背景

エンジニアがキャリアについて悩んだ際、以下の課題がある:

- 信頼できるキャリア相談相手がいない(社内では本音を話しにくい、社外には適切な相手がいない)
- 既存の転職エージェントは紹介手数料というビジネスモデル上、利害相反が否めず、純粋にキャリアにとって最善の助言が得にくい
- 汎用 AI チャット(ChatGPT等)に直接相談する方法もあるが、エンジニア特化の文脈最適化や、過去のやりとりを蓄積したキャリアプラン管理がない

### 1.2 目的・ゴール

- **手軽さ + エンジニア特化**を訴求軸として、AI とキャリアを壁打ちできる Web サービスを提供する
- 利害関係のない中立的なキャリア相談の場を作る
- 過去の対話と本人プロフィールを踏まえた、個別化されたキャリアプラン提案を可能にする

**定量目標(初期)**

| 指標 | 目標値 | 時期 |
|---|---|---|
| MAU(月間アクティブユーザー) | 5 人 | リリース後 1 ヶ月 |

※ スモールスタート前提。インフラは初期最小構成、伸びシロが見えたらスケール対応する設計とする。

### 1.3 スコープ

#### 対象(MVP = フェーズ1)

- 未ログインでの体験用壁打ち(セッション内 5 メッセージまで)
- ログイン後の本格壁打ち(履歴を踏まえた個別化応答)
- ユーザープロフィール管理(キャリア相談の質を向上させる属性入力)
- 会話履歴の保存・閲覧・再開・削除
- キャリアプランの作成・保存・編集
- スキル棚卸しテンプレートと AI 分析
- 外部求人サイトへのリンク誘導
- 認証(メール+パスワード / Google / GitHub)
- レート制限・CAPTCHA・月額 API 利用上限ガード(コスト爆発防止)
- 法的ページ(プライバシーポリシー / 利用規約 / Cookie 同意 / 13歳未満利用不可)

#### 対象外(フェーズ2以降)

- 会話・キャリアプランのエクスポート(Markdown / PDF)
- 求人 API 連携(自社 UI 内表示)
- AI による求人自動レコメンド
- フリーミアム課金(Stripe 決済)
- 求人広告表示・有料会員の広告非表示
- 特定商取引法表記ページ(有料プラン提供時に必要となるため、フェーズ2と同時に追加)
- ユーザー間のコミュニティ・公開機能(現時点では構想なし)

### 3.2 ユーザーストーリー(主要なもの)

- **未ログイン訪問者として**、登録せずに AI と試しに壁打ちしたい、なぜなら登録前にサービス価値を体感したいから
- **若手エンジニアとして**、利害関係のない AI に転職について相談したい、なぜなら社内では本音を話せず、転職エージェントは紹介手数料目当てで信用しきれないから
- **シニアエンジニアとして**、マネジメント転向か技術スペシャリスト継続かを壁打ちしたい、なぜなら自分の整理されていない考えを言語化する相手が欲しいから
- **ログインユーザーとして**、過去の会話を踏まえた継続的なキャリア相談をしたい、なぜなら毎回ゼロから説明し直すのは負担だから
- **キャリアプランを作りたいユーザーとして**、AI 対話の結果を構造化して保存したい、なぜなら口頭で終わらせず行動に落とし込みたいから
- **スキル棚卸しをしたいユーザーとして**、テンプレートに沿って経験を整理したい、なぜなら自分の市場価値を客観視したいから

## 4. 非機能要件

### 4.1 性能

- **想定同時接続ユーザー数**: 初期 1〜2 名、半年で 10〜20 名想定
- **想定データ量**: 1 年で 1〜10 万メッセージレコード、ユーザー数百名
- **レスポンスタイム目標**:
  - 画面表示: 2 秒以内
  - AI 応答開始(初回トークン): 3 秒以内(ストリーミング表示で体感改善)
  - AI 応答完了: 平均 10 秒以内(回答長による)
- **設計方針**: 初期は最小構成。MAU 数百〜数千への伸びに対応できるよう、AI 呼び出し層と DB 層は将来差し替え可能な構成とする(詳細は基本設計で決定)

### 4.2 可用性

- **稼働時間**: 24 時間 365 日(一般公開のため)
- **許容ダウンタイム**: 月間 4 時間以内(99.45%)。ただし計画メンテナンスは事前告知の上で除外可
- **障害時の方針**: AI API 障害時はユーザーにエラーメッセージを表示し、課金は発生させない

### 4.3 セキュリティ

#### 4.3.1 認証

- 認証方式: メール+パスワード / Google / GitHub の 3 方式
- パスワード保管: ハッシュ化必須(bcrypt 等、詳細は基本設計で決定)
- セッション管理: セッショントークンの有効期限とリフレッシュ設計を基本設計で定義

#### 4.3.2 個人情報の取り扱い

| 項目 | 取得 | 必須/任意 | 備考 |
|---|---|---|---|
| メールアドレス | 取得 | 必須 | 認証用 |
| ハンドルネーム | 取得 | 必須 | 本名は取得しない |
| 年齢 | 取得 | 必須 | 13 歳以上の確認も兼ねる |
| 現職 | 取得 | 任意 | 相談品質向上のため |
| 経歴 | 取得 | 任意 | 相談品質向上のため |
| 現年収 | 取得 | 任意 | キャリア相談の参考として |
| 目標年収 | 取得 | 任意 | キャリア相談の参考として |
| スキル | 取得 | 必須 | エンジニア特化の応答に必須 |
| 志向(志向性) | 取得 | 必須 | キャリア提案の前提 |
| 会話履歴 | 取得 | (自動保存) | ログインユーザーのみ |
| 本名 / 住所 / 電話番号 | **取得しない** | — | 個人情報リスク最小化 |

- **暗号化**: 通信は TLS 必須、DB の機密項目(年収等)は保管時暗号化を推奨(詳細は基本設計)

#### 4.3.3 監査・ログ

| 種類 | 保存期間 | 備考 |
|---|---|---|
| 会話履歴 | 無期限(ユーザー削除可) | デフォルトは保存。ユーザーが個別/一括削除できる |
| アクセスログ | 90 日 | アクセス元 IP、エンドポイント、レスポンスステータス |
| 認証ログ | 90 日 | ログイン・ログアウト・失敗 |
| 退会後データ | 30 日後完全削除 | 30 日間は復旧可能、以降は完全削除 |

#### 4.3.4 不正利用対策(厳しめ運用)

- 未ログイン: セッション 5 メッセージで強制ログイン要求
- ログイン後: 1 日あたりのメッセージ数上限(無料 30 / 暫定。運用で調整)
- 連続短時間送信や同一 IP 多数登録には CAPTCHA を表示(必須)
- 月額 API 利用上限を設定し、超過時はサービスを一時制限(任意機能だが MVP に含める)

### 4.4 運用・保守

- **バックアップ**: DB の日次自動バックアップ(マネージドサービスの標準機能を利用)
- **監視**: AI API コスト監視 / エラー率監視 / レスポンスタイム監視を最低限実装
- **障害対応**: 個人運用前提のため、24 時間体制は取らない。障害時はステータスページで告知
- **コスト管理**: AI API の月額予算アラートを設定(F-036 と連動)

### 4.5 拡張性

- ユーザー数 5 人 → 数千人への成長を想定し、以下を初期から疎結合に設計:
  - AI モデル呼び出し層(将来モデル変更が容易)
  - 認証層(認証プロバイダ追加が容易)
  - 課金・広告連携(フェーズ2追加が容易)
- 将来の機能追加(エクスポート、課金、広告、求人 API)が現行アーキテクチャを大きく変えずに可能であること

### 4.6 アクセシビリティ・対応端末

- **PC ブラウザ + スマートフォンブラウザ**の両対応(レスポンシブ Web)
- スマホファーストのデザインを前提とする
- 対応ブラウザ: 最新の Chrome / Safari / Edge / Firefox
- ネイティブアプリ化は対象外(将来検討)

## 5. 制約条件・前提条件

### 5.1 技術的制約

- 開発体制が **AI(Claude)による実装**であるため、運用負荷の小さいマネージドサービスを優先する
- AI モデル: **Claude Haiku 4.5** を採用(コスト効率、日本語品質、当開発環境との親和性を評価)
- 推奨技術スタック(基本設計で最終決定):
  - フロントエンド: Next.js (TypeScript)
  - バックエンド/DB: Supabase(認証 + PostgreSQL)
  - ホスティング: Vercel
  - 決済(フェーズ2): Stripe
- ※ 上記は推奨案。基本設計工程で正式決定する

### 5.2 ビジネス制約

- **予算**: 未定。ただし MAU 5 人前提で、初期は AI API + ホスティングで月 $10〜$50 を想定
- **スケジュール**: リリース希望日 未定(AI 開発で 4〜5 週間を目安)
- **体制**: プロダクトオーナー 1 名 + AI(Claude)による開発

### 5.3 前提条件

- ユーザーはインターネット接続可能な PC / スマートフォンからアクセスする
- 13 歳未満の利用は不可(登録時にチェック)
- 18 歳未満の利用は許可するが、利用規約で「保護者の同意が必要」と明記
- AI の回答は参考情報であり、最終的な判断はユーザー本人の責任である旨を利用規約および UI に明示する

### 5.4 法的要件

| 項目 | 必要性 | 対応機能 |
|---|---|---|
| プライバシーポリシー | 必須(個人情報保護法) | F-037 |
| 利用規約(免責含む) | 必須 | F-038 |
| Cookie 同意バナー | 必須(改正個人情報保護法 / GDPR) | F-040 |
| 13 歳未満利用不可 | 必須(プロダクトオーナー方針) | F-041 |
| 特定商取引法表記 | 課金開始と同時に必須 | F-039(フェーズ2) |

## 6. 用語集

| 用語 | 定義 |
|---|---|
| 壁打ち | ユーザーが AI と対話しながら自分の考えを整理する行為。本サービスのコア機能 |
| 未ログインユーザー | 登録せずにサービスを利用するユーザー。セッション 5 メッセージまで利用可 |
| ログインユーザー | 認証済みユーザー。履歴保存・キャリアプラン・スキル棚卸しが利用可 |

| ハイブリッド UI | 自由対話を基本とし、AI から「次は強み整理しますか?」等の提案ボタンを提示する UI |
| MVP | Minimum Viable Product。本ドキュメントでは「フェーズ1」と同義 |
| MAU | Monthly Active Users(月間アクティブユーザー) |

| R-001 | AI API コスト爆発(悪意ある大量送信、想定以上の利用増) | 高 | レート制限(F-033, F-034)+ CAPTCHA(F-035)+ 月額上限ガード(F-036)で多層防御 |

| R-003 | キャリア相談に起因するトラブル(「AI のアドバイスで転職して失敗、賠償しろ」) | 高 | 利用規約で免責明記(F-038)+ UI 常設の注意書き(F-012)+ 重要相談時の専門家紹介(F-013) |
| R-004 | 個人情報漏洩 | 高 | 取得項目を最小化(本名・住所等は取得しない)/ TLS 必須 / 機密項目の保管時暗号化(基本設計で決定)|
| R-005 | 13 歳未満の利用 | 中 | 登録時の年齢チェック(F-041)+ 利用規約明記 |
| R-006 | 一般公開直後にバズり想定超のトラフィックが来る | 中 | サーバレス構成で自動スケール / 月額上限ガード(F-036)で破綻回避 |
| R-007 | 求人サイトへのリンク誘導が広告として誤解される | 中 | 利用規約で広告ではない旨を明記 / フェーズ2 で広告導入時には広告である旨を明示 |
| R-008 | スコープが MAU 5 人想定に対して広く、開発期間が長期化 | 中 | フェーズ2 を明確に分離(エクスポート / 課金 / 広告 / 求人 API は MVP 外)/ 段階承認方式で軌道修正可能 |
| R-009 | プロダクトオーナーが個人運用のため、24h 障害対応不可 | 低 | ステータスページでの告知 / マネージド DB のバックアップ / SLA は明記しない |
| R-010 | 競合サービス(汎用 AI チャット、転職エージェント、既存キャリアプラットフォーム)への埋没 | 中 | エンジニア特化のプロンプト設計 + 履歴蓄積による継続価値で差別化 |
